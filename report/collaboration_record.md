# 大模型协作记录

开发中使用大模型辅助接口排查、代码编写和测试设计，再依据原理图、编译、仿真和板上反馈决定是否采用。系统运行时的定位、视频和控制由Zynq板端程序完成。

[真实会话摘录](collaboration_cases.md)保留三组用户提示、模型回答和纠错过程；[结构化记录](collaboration_cases.json)保留对应文字、时间及会话行号。案例选择覆盖视频接口漏接、显示与舵机控制分工，以及短暂失声续行的测试时序修正。摘录为代表性案例，不宣称包含全部历史对话。

| 案例 | 人工反馈及模型处理 | 采用依据与最终边界 |
|---|---|---|
| 视频接口排查 | 用户反馈旧版正常、新版黑屏；模型发现历史DDR视频链路TKEEP漏接并承认先前遗漏 | 历史接口排查案例。最终视频已采用三帧片上缓存，不能把该旧方案当作当前拓扑 |
| 显示与执行分工 | 用户确认标记较好但舵机迟缓，要求保留显示处理并恢复非PID跟踪 | 当前使用可信新观测驱动比例控制，显示分支单独平滑；无机械轴角编码器反馈 |
| 续行与时效 | 用户指定完赛备份，模型区分1200 ms失声保持与500 ms旧样本拒绝；随后发现测试累计1.3 s并修正 | 原始纠错见会话摘录；当前主机和PS至PL测试验证边界，整车停车仍受惯性影响 |

可复用工作流及其来源见[技能包](../skill/README.md)。优化前后对照见[优化与验证](optimization.md)。采样周期、测试日志和实际定位精度分别表述，未将合成输入误差当作整车实测结果。
